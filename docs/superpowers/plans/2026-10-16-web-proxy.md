# WEB Proxy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve Telegram's WEB proxy protocol v1 (`https` carrier) from mtglib as an exported `http.Handler`, with one new `mtglib.Proxy` entry point, and wire it into the `mtg` CLI.

**Architecture:** `mtglib/web` turns authenticated HTTP carrier requests into per-stream virtual `essentials.Conn`s (a `net.Pipe` pair pumped by the session) and hands each to `Proxy.ServeWebConn`, which skips Fake TLS and resumes mtg's normal obfuscated2 → DC → relay path. Everything unauthenticated falls through to an operator-supplied public `http.Handler`. TLS is terminated by a reverse proxy in front of mtg.

**Tech Stack:** Go 1.25, stdlib `net/http`, `net/http/httputil`, `crypto/hmac`, `crypto/aes`; testify (`assert`/`require`/`suite`) as in the rest of the repo; `go test -fuzz` for codecs. No new module dependencies.

**Spec:** `docs/superpowers/specs/2026-10-16-web-proxy-design.md`

## Global Constraints

- `go.mod` stays `module github.com/9seconds/mtg/v2`, `go 1.25.0`; no new `require` lines in phase 1.
- Nothing from `telegramdesktop/tproxy-server` is copied (no license). Behaviour comes from its `PROTOCOL.md`; code and JS are written independently.
- `mtglib` proper changes only in `proxy.go` (refactor) and new `proxy_web.go`; all WEB logic lives in `mtglib/web` (exported) — never under `mtglib/internal`.
- Logs carry event classes and counts only: never URLs, query strings, headers, tokens, or capabilities.
- Every HTTP response on an authenticated path sets `Cache-Control: no-store`; the public path gets **no** headers added by the handler.
- Wire constants: header 8 bytes; max payload 1 MiB; initial window 4 MiB per direction; DATA chunk 64 KiB; max stream id `0xFFFFFF`; ≤ 4096 frames per body; carrier batch 2 MiB; body limit 2 MiB; HELLO body ≤ 64 bytes; long poll 25 s; bootstrap lifetime 2 min; reconnect grace 2 min; tombstones 4096.
- All binary integers big-endian unsigned. Tokens: 32 bytes, 43-char unpadded base64url.
- `golangci-lint` with the repo's `.golangci.toml` must pass; the compiler on this machine is flaky — `go build -p 1 ./...` is an acceptable workaround, never a code change.
- If the build crashes, rerun; a `go test` failure in `network/v2 TestGetDNS/TestDoT` is a known network-environment failure, not a regression.

## Review Focus

1. Client `DATA` exceeding the stream's remaining receive window, or `DATA`/`WINDOW`/`CLOSE` for an id never opened → session closed (local 404 on next request), never a panic or partial apply. Pinned in Task 7.
2. Authenticated request arriving through a trusted proxy with `X-Forwarded-For: a, b` (two addresses) → local 404; the same header on a stranger request still reaches the public handler untouched. Pinned in Task 9.
3. Long-poll client disconnects mid-park → the parked goroutine exits promptly, the session survives, the next poll with the same cursor replays correctly. Pinned in Task 10.
4. `OPEN` while mtg's worker pool is full or the client IP is blocklisted → `CLOSE` for that id only, `EventConcurrencyLimited`/`EventIPBlocklisted` emitted, session and other streams unaffected. Pinned in Task 12.
5. `Handler.Shutdown` with live sessions and relays in flight → every stream's relay exits, `EventFinish` fires for each, Shutdown returns before its context deadline. Pinned in Task 11.

### Task 3: Tokens and request secret scanner

**Files:**
- Create: `mtglib/web/token.go`, `token_test.go`, `mtglib/web/scan.go`, `scan_test.go`

**Interfaces:**
- Produces (unexported, used by Tasks 6, 9, 11):
  ```go
  type tokenKind byte
  const ( tokenBootstrap tokenKind = 1; tokenSession tokenKind = 2 )
  type tokenHash [32]byte                       // sha256 of the 32 raw token bytes; map key
  type tokenSigner struct{ /* macKey []byte; filter cipher.Block */ }
  func deriveTokenKey(secretKey []byte) []byte  // HMAC-SHA256(key=secretKey, msg="mtg-web-token-key-v1"), 32 bytes
  func newTokenSigner(key []byte) (*tokenSigner, error) // len(key) must be 32
  func (s *tokenSigner) issue(kind tokenKind) (encoded string, hash tokenHash, err error)
  func (s *tokenSigner) verifyBearer(encoded string, kind tokenKind) (tokenHash, bool) // canonical 43-char base64url, MAC only (no tag), constant time
  func (s *tokenSigner) classify(raw []byte) (tokenKind, tokenHash, bool)             // len 32; tag check first, then MAC for each kind

  type secretScanner struct{ /* signer *tokenSigner; capabilities [][]byte */ }
  func newSecretScanner(signer *tokenSigner, capabilities []string) *secretScanner
  func (s *secretScanner) requestCarriesSecret(r *http.Request) bool
  ```
  Token layout: `raw[0:12]` random, `raw[12:16]` = first 4 bytes of `AES-128-ECB-encrypt(filterKey, raw[0:12] ‖ 0x00×4)`, `raw[16:32]` = `HMAC-SHA256(macKey, "tproxy-server-token-v1\x00" ‖ byte(kind) ‖ raw[0:16])[:16]`; `filterKey = HMAC-SHA256(macKey, "tproxy-server-token-filter-v1\x00")[:16]`; `macKey` = the 32-byte signer key.

  Scanner inputs: `r.URL.RequestURI()`, `r.Host`, every header name and every header value (all values). Each input is percent-decoded once (ignore errors, use raw on failure), then split into maximal runs of `[A-Za-z0-9_-]`; for every run of length ≥ 43 and every offset `i ≤ len-43`, the 43-char window is decoded with `base64.RawURLEncoding`; a decodable window matches if `classify` accepts it or it equals a capability (constant-time compare against each). First match returns true.
